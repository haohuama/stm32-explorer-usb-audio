## 1. 项目概述

### 1.1 背景
正点原子探索者 STM32F407（V2.7 老版）开发板，原厂默认音频链路为 `电脑 → USB_SLAVE(OTG_FS) → MCU → I2S → WM8978 → 喇叭`。现扩展为**三输入源、统一模拟输出**的音乐播放器。

### 1.2 目标（一句话）
把这块板做成一台"插电脑出声 / 插 TF 卡离线播 / 连蓝牙播"的三模音乐播放器，并配套一份**陌生人可完整复现**的开源文档仓库。

### 1.3 交付物
1. 一台能三模式播放的实体设备（硬件齐备 + 固件）。
2. 公开文档仓库：本项目撰写的 `README.md` / `REPRODUCE.md` / `docs/*.md`（MIT）。
3. 复现指南，使陌生人在取得等同硬件与官方 A 盘资料后能重建。

## 2. 范围

### 2.1 范围内（In Scope）
- **模式1** 电脑直传：USB_OTG_FS(Device) 数字音频 → MCU → I2S → CODEC。
- **模式2** TF 卡离线：板载 TF/SD + FATFS + WAV(PCM) 解码播放。
- **模式3** 蓝牙：外接蓝牙音频模块 → CODEC（推荐模拟 LINE-IN）。
- 统一输出链：`MCU → I2S → CODEC → MD8002A 功放 → SPK`；耳机走 PHONE。
- 模式切换 + LCD 状态显示 + 按键交互（切源 / 切歌 / 音量）。
- 调试：CH340 → USART1 仅作日志；USB 枚举/出声状态自检。

### 2.2 范围变更（⚠️ 需用户批准，见第 9 节）
| 变更 | 原因 | 影响 |
|---|---|---|
| **解除 SD 卡白名单** | 模式2 必须读 TF 卡 | 原白名单禁 SD；批准后纳入 |
| **新增蓝牙模块（外接）** | 板载无 BT，模式3 必需 | 不在原白名单；方案A 下不占 MCU 外设 |
| **模式1 改 UAC 终态** | 标准声卡免驱、体验更好 | 原"先 CDC"为过渡；CDC 退居控制/调试 |

### 2.3 范围外（Out of Scope，v1 不做）
录音、网络音频、触摸屏 UI、MP3 软解（v1 仅 WAV）、多房间/多设备、EQ/音效处理。

## 3. 技术方案与架构

### 3.1 核心思想：统一输出 + 三输入选源
```
 模式1 电脑 ─┐
             │  (数字 I2S)
 模式2 TF  ──┼──► MCU(STM32F407) ──I2S──► CODEC ──┐
             │                                   ├─► 功放 MD8002A ─► SPK
 模式3 蓝牙 ─┘  (模拟 LINE-IN 或 I2S)             └─► PHONE(耳机)
             ▲
             └─ MCU 经 I2C 写寄存器，切换 CODEC 输入源（数字/模拟混音器）
```
- **关键洞察**：WM8978/ES8388 均内置**数字(I2S)输入 + 模拟(LINE-IN)输入 + 输入混音器**。模式1/2 喂数字 I2S，模式3 接模拟 LINE-IN，MCU 用 I2C 选源，无需为每路单独布线。
- 详见 `三模式音乐播放器_项目设计.md`。

### 3.2 工具链
- STM32CubeMX（生成 HAL 工程骨架）+ Keal MDK + STM32F4 DFP（新版 Keil 需装 legacy **AC5**）。
- 调试：ST-Link/DAP 下载；CH340 驱动 + 串口助手（XCOM）看日志。
- 版本控制：Git（本地已 `init` + 首提交 `9c44701`；远程/上传待用户 PUSH_OK）。

### 3.3 各模式方案（要点）
- **模式1**：建议 **UAC 标准声卡**（ST `Audio_Standalone`，免驱，电脑识别为扬声器）；ST 库标准路径仅支持 **48 kHz**。CDC 仅作控制/调试通道。
- **模式2**：FATFS + WAV 解码（参考 V3 指南第55章 `ChunkRIFF/FMT/DATA` 解析；16 bit 立体声）。
- **模式3**：推荐**方案A**——蓝牙接收模块模拟 LINE-OUT → CODEC LINE-IN，MCU 不参与蓝牙；备选方案B 为模块出 I2S 给 MCU（更复杂）；**拒绝** HC-05 SPP 传音频（非 A2DP）。

## 4. 关键假设与待确认项（阻塞清单）

| 编号 | 假设/待确认 | 解法 | 阻塞级别 |
|---|---|---|---|
| A1 | CODEC 型号（WM8978 `0x1A` 只写 / ES8388 `0x10` 可读写） | **安全 I2C 只读探测**：写 `0x34` ACK+读 `0x35` NACK → WM8978；写 `0x20` ACK+读 `0x21` ACK → ES8388（不写寄存器） | 🔴 最高，阻塞全部出声 |
| A2 | 板版本 + V2.7 原理图（I2S/I2C/SD 引脚） | 从官方 A 盘取「3ALIENTEK探索者STM32F4开发板原理图」；禁止套用 V3 的 PB12/PB13/PC2/PC3/PC6 | 🔴 阻塞引脚定义 |
| A3 | SD 白名单解除 | 用户批准 §2.2 | 🟡 模式2 前置 |
| A4 | 蓝牙方案 + 模块采购 | 用户批准方案A/B 并采购 | 🟡 模式3 前置 |
| A5 | 模式1 UAC 或 CDC | 用户批准（建议 UAC） | 🟡 模式1 前置 |

## 5. 阶段计划（WBS + 里程碑）

| 阶段 | 名称 | 主要交付物 | 进入条件 | 退出标准 |
|---|---|---|---|---|
| **P0** | 硬件确认 | CODEC 探测结果 + V2.7 原理图 + 备份 | — | A1/A2 明确，解除 BLOCK-2/BLOCK-6，用户给 `ADAPT_OK` |
| **P1** | 工程骨架 | CubeMX HAL 工程（SYS/RCC/USART1/I2C myiic/SPI2=I2S2+DMA/USB_OTG_FS_Device/时钟树 PLL→MCLK） | `ADAPT_OK` | 编译通过、下载运行、CH340 能打印 |
| **P2** | 音频通路打通 | WM8978 驱动（2 文件 + 58 寄存器镜像）+ I2S 测试音独立出声 | P1 完成 | 板载喇叭/耳机出测试音，无破音 |
| **P3** | 模式2 TF 卡 | FATFS + WAV 解码 + 选曲/按键/LCD | P2 完成 + A3 | TF 卡 WAV 可播放、可切歌 |
| **P4** | 模式1 电脑直传 | USB 音频（UAC 或 CDC） | P2 完成 + A5 | 电脑识别声卡、播放出声 |
| **P5** | 模式3 蓝牙 | 蓝牙模块接 CODEC LINE-IN + I2C 切源 | P2 完成 + A4 | 手机/电脑蓝牙连接后出声 |
| **P6** | 统一交互 | 自动/手动选源 + LCD 状态 + 音量 | P3/P4/P5 至少两模式可用 | 三模切换正确、显示正确 |
| **P7** | 整合验收 | 三模联调 + 低噪/稳定性 | P6 完成 | 三模均出声、无明显噪声、可较长时间运行 |
| **P8** | 文档与仓库 | GitHub 上传 + 复现教程定稿 | 用户 PUSH_OK | 仓库公开、REPRODUCE 可跟做 |
| **P9** | 发布/交接 | 发布说明、后续维护建议 | P8 完成 | 交付完成 |

> **依赖与关键路径**：P0 → P1 → P2 是所有模式的根；P3/P4/P5 并行于 P2 之后；P6/P7 收口。最关键路径是 **P0（硬件确认）**，它不动，后面全停。

## 7. 风险登记（Risk Register）

| 风险 | 影响 | 缓解 |
|---|---|---|
| R1 CODEC/版本未确认 | 全部出声阻塞 | I2C 只读探测 + 取真 V2.7 原理图（A1/A2） |
| R2 蓝牙模块接口不匹配 | 模式3 失败 | 方案A 模拟 LINE-IN，几乎零风险；选型前核对模块引脚 |
| R3 三路采样率/格式不统一 | 爆音/不同步 | CODEC 内部处理或统一为 48 kHz；WAV 按文件头适配 |
| R4 版权（公开仓库再分发 A 盘资料） | 法律/合规 | `REPRODUCE.md` 指引自取；`.gitignore` 排除 `资料/`；本项目文档 MIT |
| R5 白名单冲突（SD/USB Host/额外 UART） | 模式2/3 难落地 | 用户批准 §2.2 范围变更 |
| R6 时间/精力不足 | 进度拖延 | 分阶段交付，先单模式；文档先行降低认知负担 |

## 8. 验收标准（Definition of Done）
1. 三种模式均能**独立出声**（电脑/ TF / 蓝牙）。
2. 模式切换正常，LCD 正确显示当前模式/曲目/音量。
3. 音量可调，无明显破音/严重底噪。
4. 陌生人按 `REPRODUCE.md`（硬件齐备时）能复现搭建过程。
5. 仓库文档（MIT）完整、无第三方版权材料入库。
