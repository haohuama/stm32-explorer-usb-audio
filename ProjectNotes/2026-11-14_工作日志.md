- **🔴 选曲协议升级（关键）**：DTR/RTS 只有 2 位（3 还是端口刚打开时的默认态），最多表达 3 首，无法支撑第 4 首。改为 **`SET_LINE_CODING` 的波特率字段编码**：
  - 上位机 `ser.baudrate = 100000 + idx` → usbser 发 `CDC_SET_LINE_CODING(0x20, 7B)`，前 4 字节 LE 就是 baudrate。
  - 设备端 `CDC_Control_FS` 的 `case CDC_SET_LINE_CODING` 里：先照常保存 linecoding，再判 `100000 <= baud < 100016` → `lcd_ui_select_song(baud-100000)`。
  - **占 0 字节音频带宽**，且可扩展到任意首数。DTR/RTS 保留为 0..2 的兼容通道（wv<3 时生效，wv==3 忽略）。
  - 注意：`usbd_cdc.c` 里 SET_CONTROL_LINE_STATE(wLength==0) 传的是 `(uint8_t*)req`（Setup 指针），SET_LINE_CODING(wLength=7) 走 CtlPrepareRx → `EP0_RxReady` 里才回调 `Control(0x20, hcdc->data, 7)`，所以两条路径拿到的 pbuf 语义不同。

## 定位到一个真 bug：restore_rect 裁剪用了 TOP_H → 无符号下溢 → 开机卡死

现象（用户拍照+设备管理器截图）：
- 屏上左栏画好了（封面照片、Lil Tjay、进度条），**右栏整片蓝、没有歌词**
- 设备管理器里**根本没有「端口(COM 和 LPT)」**，只有一个不认识的 USB Composite Device
- 我这边 `list_ports` 扫不到任何串口

根因：改成「左1/3图片 + 右2/3歌词」后，文字区从 y≈52~196 搬到 y≈266~374，
而 `restore_rect()` 里的裁剪还写着：

```c
if (y + h > TOP_H) h = (uint16_t)(TOP_H - y);   // TOP_H = 240
```

- 暂停 = 停止发送（环形排空即静音）；写失败自动重连并从当前位置续播。
