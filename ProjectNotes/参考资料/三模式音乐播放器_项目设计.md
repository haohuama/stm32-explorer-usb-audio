# 三模式音乐播放器 · 项目设计（V0.1 草案）

> 提出时间：2026-11-12
> 状态：**方向草案，待用户拍板 + 硬件确认后启动固件**
> 前置：仍受 `ADAPT_OK` 阻塞（CODEC 身份 / V2.7 原理图未确认）。本设计不写任何工程代码，仅定架构与计划。

---

## 0. 目标一句话

把探索者 STM32F407 板做成一台**三输入源、统一模拟输出**的音乐播放器：

| 模式 | 输入源 | 音频怎么来 |
|---|---|---|
| 模式1 | 电脑直传 | USB（OTG_FS，Device）数字 PCM |
| 模式2 | TF 卡离线 | 板载 TF/SD 卡，FATFS + WAV 解码 |
| 模式3 | 蓝牙 | 外接蓝牙音频模块 → 模拟 LINE-IN（推荐）或 I2S |

三种模式**共用同一输出链**：`MCU → I2S → CODEC(WM8978/ES8388) → 功放(MD8002A) → SPK 绿端子`，耳机走 `PHONE`。

---

## 1. 系统架构（核心思想：统一输出 + 三输入选源）

```
                ┌─────────── 模式1: USB_OTG_FS(PA11/PA12, Device) ──┐
                │   电脑 → USB Audio(数字PCM) → MCU                │
                │                                                  ▼
  输入源选择 ──► MCU(STM32F407) ──I2S(数字)──► CODEC ──┐
   (KEY 切换    (FATFS/USB栈/   ◄── I2C 控制 ──┘      │
    或自动检测)  蓝牙透传)                             │
                │                                      ▼
                └─────────── 模式2: TF/SD 卡 ──WAV解码─┘   CODEC 内置混音器
                            (FATFS + PCM)              (数字 I2S / 模拟 LINE-IN 选源)
                                                      │
                ┌─────────── 模式3: 蓝牙模块 ──────────┘
                │   手机/电脑 → BT → 模拟LINE-IN 或 I2S
                                                      ▼
                                             功放 MD8002A → SPK
                                             + PHONE(耳机)
```

**关键洞察**：WM8978/ES8388 都内置 **数字(I2S)输入 + 模拟(LINE-IN)输入 + 输入混音器**。
- 模式1、模式2 → MCU 经 I2S 送**数字**音频到 CODEC；
- 模式3 → 蓝牙模块送**模拟**音频到 CODEC 的 LINE-IN；
- MCU 只通过 I2C 写寄存器切换"当前用哪个输入"，无需为每路单独布线。

## 2. 硬件现状与待确认清单（诚实）

| 项 | 现状 | 影响 |
|---|---|---|
| CODEC 型号 | **未确认**（WM8978 `0x1A` 只写 / ES8388 `0x10` 可读写），丝印被 LCD 挡 | **阻塞一切出声**，最高优先 |
| 板版本 | 疑似 V2.7 老版，但**缺真原理图**；用户 `D:\4，程序源码\` 与 V3 指南均为 V3+ES8388 | I2S/I2C/SD 引脚待定 |
| USB_SLAVE | PA11/PA12（OTG_FS，芯片固定） | 模式1 可用 |
| TF/SD 槽 | 板载（V3=Micro SD/SDIO；V2.7 待核） | 模式2 可用，但见 §5 白名单冲突 |
| 蓝牙 | **板载无**，必须外接模块 | 模式3 新增硬件 |
| 调试 | CH340 → USART1(PA9/PA10) 仅日志 | 不变 |
| 显示/按键 | 板载 TFT LCD + KEY0/1/2/WK_UP | 模式切换/音量/曲目显示 |

**第一步永远是先解 CODEC + 版本**（用已设计好的"安全 I2C 只读探测法"：写 `0x34`/读 `0x35` → WM8978；写 `0x20`/读 `0x21` → ES8388）。

## 3. 三种模式实现方案

### 模式1 · 电脑直传（USB Audio）
- **推荐 UAC（USB Audio Class，标准声卡）**：免驱，电脑把它识别成"扬声器"，即插即用。ST 官方 `Audio_Standalone` 例程可直接移植。
- 数据流：`电脑 → USB_OTG_FS(Device) → MCU(USB Audio, 同步传输) → I2S → CODEC`。
- 频率：ST USB 库标准路径**只支持 48 kHz**（`USBD_AUDIO_FREQ`）；要 44.1 kHz 需自定义或外部时钟，v1 先接受 48k。
- CDC 退居"控制/调试通道"（音量、模式切换命令），不作音频载体。
- 注：原项目"先 CDC"是过渡简化；本产品形态下 **UAC 才是模式1 的正确终态**，建议直接做 UAC。

### 模式2 · TF 卡离线
- 板载 TF/SD + **FATFS** + **WAV(PCM) 解码**（参考 V3 指南第55章 / 实验43 的 WAV 解析：`ChunkRIFF/FMT/DATA`，16bit 立体声）。
- 数据流：`TF卡 → FATFS读文件 → PCM → I2S → CODEC → SPK`，LCD 显示曲目/进度，按键切歌/暂停。
- ⚠️ **范围变更**：原项目白名单**禁 SD 卡**，本模式必需，须用户确认**解除 SD 卡禁用**（见 §5）。
- 升级项（v2）：MP3 需解码器——软件解码（占用 CPU）或外接 VS1053/解码模块。v1 仅 WAV。

### 模式3 · 蓝牙音频
- 板无蓝牙，**外接模块**。两方案：
  - **方案A（推荐，最省事最稳）**：蓝牙音频**接收**模块（如 BK3254 / OVC3860 / JL 类 "蓝牙音频接收模块"），输出**模拟 LINE-OUT** → 接 CODEC 的 **LINE-IN**。MCU **完全不参与蓝牙**，只保持 CODEC 上电并把输入切到模拟。模块自带配对/连接，手机电脑直接连。
  - **方案B（更集成但更复杂）**：蓝牙模块输出 **I2S** → MCU 作 I2S 从机收流 → 再送 CODEC。需 MCU 多一路 I2S 或从机角色，调试成本高。
  - ❌ 拒绝：HC-05/06 这类 **SPP 串口透传**模块传音频——带宽和实时性都不支持 A2DP 音乐，不可用。
- 方案A 还顺带**规避了"额外 USART"需求**（白名单只列了 CH340 调试串口），蓝牙模块独立工作，不占 MCU 外设。

## 4. 模式切换与交互
- **手动**：KEY 循环切换模式；另一 KEY 调音量（写 CODEC 音量寄存器）。
- **自动（推荐 v1）**：上电检测——USB 插入且枚举成功 → 模式1；蓝牙模块"已连接"脚拉高 → 模式3；否则默认模式2（TF）。
- **显示**：TFT LCD 显示当前模式图标、曲目名、音量条。
- 模式切换本质 = MCU 经 I2C 改 CODEC 输入选择寄存器 + 切换 MCU 数据来源（USB/TF/旁路）。

---

## 5. 范围变更声明（需用户拍板）
1. **解除 SD 卡白名单** —— 模式2 必需。其余仍禁（以太网/USB Host/CAN/触摸/串口屏/DMA2D/RTC/ADC）。
2. **新增外设：蓝牙模块** —— 不在原白名单，但模式3 必需，且为**外接独立模块**（不占板载 MCU 资源，方案A 下甚至不占任何 MCU 外设）。
3. 模式1 由"先 CDC"升级为 **UAC 终态**（CDC 仅留控制/调试）。

---

## 6. 风险与里程碑
- **R1（最高优先，阻塞）**：CODEC/版本未确认 → 先做安全 I2C 探测 + 搞到真 V2.7 原理图。
- **R2**：蓝牙模块模拟/数字接口与 CODEC 输入匹配（方案A 几乎无风险）。
- **R3**：三路输入采样率/格式统一到 CODEC（USB 48k、TF 按文件、BT 模块定）。
- **里程碑**：
  - M0 硬件确认（CODEC + 引脚 + SD 接口 + BT 模块到位）
  - M1 **任一模式先出声**（建议从模式2 TF 或模式1 UAC 二选一打穿链路）
  - M2 三模式齐备 + 切换 + LCD/按键交互
  - M3 体验打磨（音量/曲目/自动切换/低噪）
