## 1. 总体原则与边界（最重要）

**全流程自动化 = 我自动做一切可自动化的 + 你在物理/签字环节介入**，诚实分成三类：

- **A 类 · 我全自动**：资料分析、文档撰写、规划、代码编写（授权后）、脚本生成、本地 Git、任务跟踪、进度日志、复现指南维护。
- **B 类 · 我准备 + 你执行物理**：I2C 只读探测、ST-Link 烧录、听音判定、读丝印、硬件接线、物料采购。
- **C 类 · 需你签字/授权**：`ADAPT_OK`、解除 SD 白名单、范围变更批准、联网/下载许可、`PUSH_OK`。

**红线（绝不自动化、绝不越权）**：
- 不烧录、不改跳线、不看丝印、不听音；不声称"已烧录/已出声/已枚举/已上传"。
- 不自动 `git push`（连接器 disconnected + 规则禁自动上传）；远程推送必须你 `PUSH_OK` + 凭证。
- `SOURCE_OK` 前不写 USB 协议栈 / WM8978 寄存器初始化 / I2S DMA 配置；`ADAPT_OK` 前不进入代码适配。

## 4. 我使用的自动化手段（实际可用工具）

- **任务编排**：`TaskCreate/TaskUpdate/TaskList` 每阶段建任务，标记 `in_progress`/`done`；同一失败连续 1 次即 `STEP_FAILED` 停（遵守规则）。
- **脚本化**：Python 隔离 venv（`pypdf` 抽取、`re` 解析 I2C 日志、`wave` 生成测试音、Jinja/字符串模板渲染代码骨架、静态检查）。
- **版本**：Git 本地自动 `commit`（已 `init`，首提交 `9c44701`）；远程待你 `PUSH_OK`。
- **定时提醒**：`automation_update` 建"每日/每周"周期性任务，催你做 B 类物理闸门与进度核对（如"请执行 I2C 探测并回传""请确认本周是否可给 ADAPT_OK"）。
- **文档**：随阶段自动更新 `README.md` / `REPRODUCE.md` / `项目计划书.md` / 本安排。
- **知识复用**：`atk_explorer_doc_digest`（已装）；后续可按需沉淀 CubeMX/HAL 脚手架、WM8978 驱动 skill。

## 6. 为什么不能 100% 无人值守（诚实清单）

1. **物理操作需手**：探测、烧录、听音、读丝印、接线、采购——远程无法完成，也不该由我越权（安全/责任）。
2. **签字是责任边界**：`ADAPT_OK`（确认硬件）、`PUSH_OK`（公开发布）必须由你拍板。
3. **工具可用性**：CubeMX/Keil 多为 GUI，未必有命令行；若无，我交付"可粘贴配置 + 手写骨架"，由你在 GUI 落地。
4. **联网/下载受限**：此前约定"未联网"；抓取 datasheet/A 盘需你单独放行。
