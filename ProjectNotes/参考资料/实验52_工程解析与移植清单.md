## 2. 编译 / 烧录 / 电脑端识别步骤（人工执行，智能体不执行）

### 2.1 编译（Keil MDK）

1. 用 Keil uVision5 打开 `实验52 USB声卡(Slave)实验\Projects\MDK-ARM\atk_f407.uvprojx`。
2. 确认 `Options for Target → Device` 为 `STM32F407ZGTx`；若提示缺 Pack，安装 `Keil.STM32F4xx_DFP`（本机 `E:\Keil.STM32F4xx_DFP.3.1.1` 有痕迹）。
3. 选 Target **`USBD_AUDIO`**；编译宏保持 `STM32F407xx,USE_USB_FS`，**不要**自行改编译器版本或优化等级（`<Optim>1`）。
4. `Project → Rebuild all target files`（F7）。包含路径已指向 `Drivers / Middlewares / User / USB_APP / USB_HAL / Class\AUDIO\Inc / Core\Inc`，一般无需手动加。
5. 产物：`Output\atk_f407.hex`（`CreateHexFile=1` 已开）。若只想验证流程，也可直接用目录里现成的 hex。
6. 预期：0 Error 0 Warning（或仅有未使用变量警告）。这份工程与 CODEC 型号无关的部分能正常编译——**编译通过不代表能在 V2.7 板上出声**。

> 说明：这是正点原子自有的寄存器版 BSP + ST HAL USB 栈混合工程，**不是 CubeMX 生成工程**，因此不存在 `USER CODE BEGIN/END` 区段。若将来并入 CubeMX 工程，必须新建 `.ioc` 并把改动放进 USER CODE 区间（提示词规则 9）。

### 2.2 烧录（人工）

**方式 A — SWD 调试器（推荐）**
1. ST-Link / J-Link 接 `SWDIO=PA13`、`SWCLK=PA14`、`GND`；板子独立供电时**不要**接 3.3V。
2. Keil：`Options for Target → Debug` 选对应调试器；`Utilities → Use Target Driver for Flash Programming`，Flash 算法 `STM32F4xx_1024.FLM`。
3. `Download`（F8）或 `Load` 烧 `Output\atk_f407.hex`，复位运行。
4. 若连不上：按上电五步法查供电 / 复位 / 晶振 / BOOT0 / SWD 连线；`SYS→Debug` 若被设为 No Debug，PA13/PA14 会被释放。

**方式 B — 串口 ISP（一键下载）**
1. USB 线接 **USB_UART**（CH340），`P10` 跳线帽把 PA9/PA10 接到 RXD/TXD。
2. BOOT0 置 1 → 复位进 system bootloader；用 FlyMcu / mcuisp 选 hex，勾 DTR/RTS 一键下载。
3. 下载完 BOOT0 回 0，复位运行。

> **边界声明**：以上均为给你执行的步骤。智能体不烧录、不调 OpenOCD、不插拔线缆、不改跳线；不声称「已烧录 / 已枚举 / 已出声」。

**故障域切分（很重要）**：USB 枚举只依赖 USB 栈，不依赖 CODEC；而 `Audio_Init → BSP_AUDIO_OUT_Init → es8388_i2s_cfg` 会通过软件 IIC 向地址 `0x10` 写寄存器。若 V2.7 板上是 WM8978（`0x1A`），可能出现两种结果：
- 枚举成功、设备管理器有声卡，但 **CODEC 未配置 → 完全无声**；
- 软件 IIC 等 ACK 阻塞 / 超时，导致 USB 配置阶段卡住 → **连枚举都失败**。

无论哪种，都不能据此判断「WM8978 坏了」。先用串口/LCD 定位卡在哪一步，再按第 3 节替换 CODEC 层。

## 4. 四件套

**① 原理说明**
USB UAC 声卡的数据链是：电脑（等时 OUT 包，48 kHz/16 bit/立体声）→ USB_OTG_FS ISOC EP1 → `usbd_audio.c` 环形缓冲（`AUDIO_TOTAL_BUF_SIZE`）→ `USBD_AUDIO_fops.AudioCmd/PeriodicTC` → `usbd_audio_if.c` → `BSP_AUDIO_OUT_Init/Play` → `stm32f407_audio.c` → I2S2 + DMA1 Stream4 双缓冲 → CODEC → SPK/PHONE。USB 枚举与 I2S 出声是两段独立链路，CODEC 驱动只影响后者（以及初始化阶段会不会卡住）。这也是为什么「编译通过」不等于「能出声」。

**② 完整代码**
**本轮零代码产出、零文件修改**：按你的指令只「列出需要修改的地方」，且项目仍处于「暂停代码适配、待丝印确认」状态。第 3 节是原文 → 改后方向的对照清单，不是已应用的补丁。真正动手需 `SILKSCREEN: WM8978` + `ADAPT_OK`，届时按提示词规则 8 给出完整文件 / 函数 / 插入位置的「原文片段 → 改后片段」，并遵守 CubeMX `USER CODE BEGIN/END`。

**③ 预期现象**
- 你现在能得到：本解析文档；D 盘两个原始工程**原封不动**；项目状态仍为「资源就绪、代码适配暂停」。
- 若按第 2 节在**对应硬件**上执行：编译 0 Error；烧录成功；设备管理器出现 `STM32 AUDIO Streaming in FS Mode`（VID_0483 / PID_5730）；LCD `USB Connected`；LED1 常亮、LED0 闪烁。
