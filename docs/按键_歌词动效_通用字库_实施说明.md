|---|---|---|

### 播放/暂停怎么落地的

板子没有存储，声音只能由电脑经 USB 送，所以**真正的暂停只能由电脑执行**。
做法：按键 → 板子通过 CDC **IN** 端点（上行）发 1 个字节 → 电脑端脚本收到后暂停/继续/切歌。

| 字节 | 含义 | 电脑端动作 |
|---|---|---|
| `'P'` | 暂停 | 停止发 PCM（环形排空后自动静音，歌词时间轴跟着停） |
| `'R'` | 继续 | 恢复发送，并把暂停掉的时长从时间基准里扣掉（不会补播快进） |
| `'N'` | 下一首 | 跳到列表下一个 WAV |
| `'B'` | 回开头 | `wf.rewind()` 重放当前曲 |

电脑端要加 `--keys` 才会起读线程；不加时设备发出去没人收，返回 busy 直接丢弃，
**不影响下行 PCM**（IN/OUT 是两条独立管道）。

> 说明：`'B'` 目前是"重播当前曲"而不是"上一首"——播放列表是按文件顺序流的，
> 往回跳需要重建列表索引，改动面较大，先留这个语义。

- PE2/3/4 未被 FSMC 屏占用（屏用 NE4+A6 → PD/PE7-15/PF12/PG12/PB15），无冲突
- 消抖：连续 2 次采样一致才认（主循环 10ms 一次）
- 长按：音量键按住 700ms 后每 150ms 重复，短按一次跳 4 档
- **觉得上下/左右反了**：只改 `key.c` 顶部 4 个 `MAP_KEYx` 宏即可

音量走 `WM8978_SPKvol_Set(0..63)`（模拟增益），默认 0x30；屏上左下角显示 `VOL nn`，
串口同时打印 `[KEY] VOL=48/63`。

切歌走 `lcd_ui_select_song(idx)` → 换封面 + 换歌词 + 时间轴归零。
⚠️ **音频仍由电脑送**，按键只切屏上曲目；声音要跟着换得在电脑端换文件（见 §5）。

## 2. 歌词动效（当前句一直变色）

`lcd_ui.c` 新增 `hsv565()` / `dim565()`：
- 当前句原文 = 彩虹色（色相每 22ms 走 1，约 **5.6 秒一圈**）
- 译文 = 同色相压暗（`k=150`），左侧指示条跟原文同色
- **只在真正播放时动**（`played_ms` 有变化），暂停/无数据立即停住，不会空转刷屏
- **只重画当前那一块**（约 52 行 × 800 像素），不动其他歌词 → 每帧约 3ms，9fps

## 3. 通用字库（一般汉字都有）

`Tools/gen_cn_font.py` 改为默认生成**整个 GB2312**（全角符号 + 一二级汉字）：

| 项 | 改前（只挑用到的字） | 改后（全 GB2312） |
|---|---|---|
| 字数 | 655 | **7478** |
| 点阵体积 | 20.5 KB | **239 KB** |
| 影响 | 加新歌词必须重跑脚本，否则出现空方块 | **任何中文歌词都能显示，不用再生成字库** |

`cn_bits()` 从线性查找改成**二分查找**（表按 GBK 升序，13 次比较搞定），
否则每次换行要扫 7478 项。

想退回精简模式：`py Tools/gen_cn_font.py --used`。

## 6. 关于「不重烧就能加歌词/图片」——没有 TF 卡时的可行路线

音频本来就要求电脑在场（USB CDC 送 PCM），所以**歌词/封面完全可以跟音频走同一条 USB 线**：

- 电脑端脚本额外读 `.lrc` 和图片 → 打成一串控制帧发下去
- 设备端在「控制模式」下收帧：lrc 文本直接替换内存里的歌词表；图片按行流式画到屏上
  （240×240 RGB565 = 115KB，RAM 放不下，所以**边收边画**）
- 控制模式与 PCM 用 `SET_LINE_CODING` 的波特率做开关（现有 100000+idx 选曲就是这么做的），
  **播放期间不解析任何控制帧 → 不影响当前音频链路**

这条路线不依赖任何新硬件，做完就能「改歌词/换封面只改电脑端文件、板子不用重烧」。
