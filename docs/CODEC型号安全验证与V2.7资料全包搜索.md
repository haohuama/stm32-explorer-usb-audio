## 3. 安全判型的原理：两颗芯片的 I2C 身份不同

不用看丝印、不用拆屏、不用原理图——**芯片自己在 I2C 总线上会报身份**。这是只读探测：主机发「地址 + 读写位」，芯片用 ACK 回答，全程**不写任何寄存器**，不会改变芯片状态，更不会损坏硬件。

### 3.1 已核实的地址与读写特性（有出处）

| 特性 | WM8978 | ES8388 | 出处 |
|---|---|---|---|
| 控制接口 | 2 线（I2C）或 3 线，由 `MODE` 脚选择（Low=2 线） | 2 线 I2C | WM8978 datasheet Rev4.5 p82 Table 63；`es8388.c:38` |
| 7 位器件地址 | **固定 `0011010` = `0x1A`** | **`0x10`**（代码中 `ES8388_ADDR 0x10`，注释「固定为0x10」） | datasheet p83「In 2-wire mode the WM8978 has a fixed device address, 0011010」；`es8388.h:30` |
| 总线上发送的字节 | 写 `0x34` = `(0x1A<<1)|0`；读 `0x35` = `(0x1A<<1)|1` | 写 `0x20` = `(0x10<<1)|0`；读 `0x21` = `(0x10<<1)|1` | `wm8978.c:79`；`es8388.c:83,117,130` |
| **读写特性** | **只写**：datasheet p82 原文「If … the R/W bit is '1' **when operating in write only mode**, the WM8978 returns to the idle condition」→ 发读命令**不会 ACK** | **可读可写**：`es8388.c` 有 `es8388_read_reg()`，发 `0x21` 读并 ACK | datasheet p82；`es8388.c:115-138` |
| 寄存器宽度 | 7 位寄存器 + 9 位数据（16 位控制字） | 8 位寄存器 + 8 位数据 | datasheet p82；`es8388.c:79-101` |

### 3.2 判定矩阵（双重判据：地址 + 读写）

| 探测结果 | 判定 |
|---|---|
| `0x34`（WM8978 写）**ACK**，且 `0x35`（读）**NACK** | ✅ **WM8978 在位**——与 datasheet 只写特性完全吻合 |
| `0x20`（ES8388 写）**ACK**，且 `0x21`（读）**ACK** | 🔴 **ES8388 在位**——按提示词规则 1 停主线、另开分支 |
| 两者都 ACK | 异常（总线上有两颗 CODEC 或地址冲突），需人工复核，**不下结论** |
| 两者都 NACK | 见第 5 节排查（供电 / 总线引脚 / 上拉 / MODE 脚） |

> **为什么比看丝印更可靠**：丝印可能磨损、被挡、被打磨改标；I2C 地址是芯片内部硬连的，无法伪装。且双重判据（地址 + 只写/可读）同时满足才下结论，误判概率极低。

## 4. 方法一（推荐）：万用表 + 现成工程，零新增代码

**适用**：你不想写/烧任何测试程序。用 D 盘 HAL 版实验52 已有的软件 IIC + es8388 驱动，做**只读**探测。

### 4.1 断电万用表预检（先排除硬件问题，30 秒）

| 步骤 | 操作 | 目的 / 判据 |
|---|---|---|
| W1 | 断电，电阻档测 **PB8(SCL) 对 3.3V**、**PB9(SDA) 对 3.3V** | 应有上拉电阻（探索者 typically 4.7 kΩ）。若开路 → 总线引脚不对或没上拉，先解决 |
| W2 | 断电，测 PB8 与 PB9 之间电阻 | 不应接近 0 Ω（短路）；若短路，先排障 |
| W3 | 通电（仅 USB_232 供电或独立 5V），测 CODEC 供电脚 | 需原理图才知道哪只脚，**本包无 V2.7 原理图 → 此项跳过**，不要盲测 |
| W4 | 确认 USB/CAN 跳线置 **USB 侧**，跳线帽未松动 | 与 CODEC 判型无关，但影响后续 |
| ⚠️ | **禁止**用电阻档在带电状态测引脚；**禁止**用二极管档/通断档直接戳芯片引脚（可能损坏） | 安全红线 |

> W1/W2 的 PB8/PB9 来自 V3 图纸与 HAL 工程 `myiic.h`，是**纸面候选**；老版 V2.7 的 IIC 脚位未经原理图确认（项目约定「不自行指定引脚号」）。所以 W1/W2 只作**参考排查**，不能作为判型依据。真正的判型靠第 3.2 节 I2C 扫描——它会自己找出哪对引脚有 ACK。

### 4.2 用现成 es8388 驱动做只读探测（不改工程、不重编译）

D 盘 HAL 版实验52 的 `es8388.c` 已有 `es8388_read_reg()`（读 `0x21`）。思路：

1. **用现成 `Output\atk_f407.hex` 直接烧录**（已编译产物，无需 Keil、无需改源码、无需 AC5）。
2. 上电后观察串口 `EVAL_AUDIO_Init` 打印与 LCD 状态。工程会调用 `es8388_init()` → 向 `0x10` 写序列。
3. 判据（**间接**，需谨慎）：
   - 若 LCD 显示 `USB Connected`、串口打印 `EVAL_AUDIO_Init:70,48000`、且后续无错误 → 说明 `0x10` 有 ACK → **倾向 ES8388**。
   - 若程序卡在 `es8388_init()`（`iic_wait_ack()` 250 次超时后返回非 0）或 LCD 无音频初始化完成 → `0x10` 无 ACK → **倾向 WM8978（0x1A）或其他**。
4. ⚠️ **局限**：`es8388_init()` 的失败可能被上层忽略（`main.c` 未检查返回值），且软件 IIC 超时 250 次后继续跑，现象可能是「USB 枚举成功但无声」，不直观。**此方法只能给倾向，不能定论**。

> 结论：4.2 适合「快速粗筛」，真正确认请用 4.3 的最小只读扫描。

### 4.3 最小只读 I2C 扫描测试（推荐，需你自行编译烧录）

**边界**：我**不写入 D 盘任何工程文件**，只在此给出可直接粘贴的源码；你是否新建工程、是否烧录，由你决定；智能体不烧录、不接线。

**做法**：在 Keil 新建一个**最小工程**（Target `STM32F407ZGTx`，AC5 或 AC6 均可，只需 `core_cm4.h` 级寄存器操作），只做：初始化 PB8/PB9 为开漏 + 上拉 → 遍历 `0x08..0x77` 所有 7 位地址 → 对每个地址发 **START + 写地址字节 + 等 ACK** → 若 ACK 再发读地址字节看是否 ACK → STOP → 串口打印。**不初始化 USB、I2S、DMA、CODEC 寄存器**，只探测地址。

核心扫描逻辑（伪代码，供你写成 Keil C）：

```c
/* 只做 I2C 地址探测，不写任何寄存器；PB8=SCL, PB9=SDA（纸面候选，代码可改） */
for (addr = 0x08; addr <= 0x77; addr++) {
    iic_start();
    ack_w = iic_send_byte((addr << 1) | 0);   /* 写地址 */
    iic_stop();
    if (ack_w == 0) {                          /* 有器件应答 */
        iic_start();
        ack_r = iic_send_byte((addr << 1) | 1);/* 读地址：WM8978 应 NACK，ES8388 应 ACK */
        iic_stop();
        printf("ACK 7bit=0x%02X  W=0x%02X  R_ack=%d\r\n",
               addr, (addr << 1), (ack_r == 0));
    }
}
```

**预期输出与判定**：

```
ACK 7bit=0x1A  W=0x34  R_ack=0     → WM8978（地址 0x1A + 只写）  ✅
ACK 7bit=0x10  W=0x20  R_ack=1     → ES8388（地址 0x10 + 可读写）🔴
ACK 7bit=0x50  W=0xA0  ...          → 板上 24C02 EEPROM（正常，忽略）
ACK 7bit=0x68  W=0xD0  ...          → 板上 MPU6050（若有，忽略）
```

**安全性**：
- 只读探测 = 发地址帧 + 等 ACK + STOP，**不发送寄存器地址和写数据**；
- 对 WM8978 发读地址帧会被忽略（datasheet p82 明确写「R/W bit is '1' … returns to idle」），**不会触发任何写操作**；
- 最坏情况：总线引脚不对 / 无上拉 → 扫不到任何 ACK → 无结论，**不会损坏芯片或板子**。

**若扫不到**：按顺序排查（见第 5 节）——换 IIC 引脚对（PB10/PB11、PB6/PB7 等候选）、查上拉、查供电、确认没有把 CODEC 的 `MODE`/`CSB` 脚配成 3 线模式。

## 5. 方法二备选 / 扫不到时的排查

### 5.1 工具备选（如果你有）

| 工具 | 做法 | 优点 |
|---|---|---|
| **USB-I2C 适配器**（CH341 / PCF8574 板 / Bus Pirate） | 接 PB8/PB9 + GND，电脑上跑 I2C 扫描（如 `i2cdetect -y 1`） | 不烧录 MCU、不写任何代码，纯外部只读扫描 |
| **逻辑分析仪**（Saleae / 低成本 LA） | 接 SCL/SDA，跑现成 `atk_f407.hex`，抓启动阶段的 I2C 波形，看地址帧 `0x34` 还是 `0x20` | 完全旁路观察，最安全；还能看到 ACK 波形 |
| **示波器** | 单通道看 SDA，触发 START，数前 8 位 | 最简单，但读 ACK 需双通道 |

### 5.2 扫不到 ACK 的排查清单

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 所有地址无 ACK | IIC 引脚不是 PB8/PB9 | 换候选：`PB10/PB11`（I2C2）、`PB6/PB7`（I2C1）、`PC9/PC10`（I2C3）；逐个试扫 |
| 所有地址无 ACK | 总线无上拉 | 断电测 PB8/PB9 对 3.3V 电阻；若开路，临时外接 4.7 kΩ 上拉到 3.3V（**仅在你确认电气安全时**） |
| 所有地址无 ACK | CODEC 未供电 / 在复位 | 需 V2.7 原理图定位电源脚；无原理图时**不要盲测**，停在此处 |
| 扫到 `0x1A` 但 R_ack=1 | WM8978 只写（符合预期） | 判定 WM8978 ✅ |
| 扫到 `0x10` 但 R_ack=0 | ES8388 可读写（符合预期） | 判定 ES8388 🔴 |
| `0x1A` 和 `0x10` 都 ACK | 总线上有两颗 / 地址冲突 | **不下结论**，人工复核硬件 |
| `MODE` 脚被拉高（3 线模式） | WM8978 不在 I2C 总线上 | 需确认 `MODE` 脚电平；无原理图时不要猜，改用逻辑分析仪看 3 线时序 |

> **禁止**：为「试出结果」而向未知地址随意写寄存器、反复软复位、或短接芯片引脚。这些不是只读探测，可能改变状态或造成损伤。
