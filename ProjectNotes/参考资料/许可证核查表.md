## 0. 关于「已登录浏览器会话」的说明（先讲清楚，不编造）

用户指定用当前浏览器已登录的 GitHub 会话。实测环境：

|---|---|

**结论：本环境无法接入「当前浏览器已登录的 GitHub 会话」**。浏览器自动化工具启动的是**独立 Chromium 实例 + 独立 profile**，不共享用户现有浏览器的 Cookie / 登录态；本机也没有可连接的调试端口。实际打开 GitHub 页面后，快照里始终显示 `Sign in` / `Sign up`，证实该实例**未登录**。因此**没有**使用任何登录态、没有读取或使用任何凭据、没有以用户身份执行任何操作。

不过仍用该独立浏览器**实际执行了页面检索与许可证页面核对**（会话结束已 `close`，未留后台进程）：

## 4. 合规判定与 Phase 8 前置条件

| 等级 | 处理 |
|---|---|
| MIT（且芯片/库匹配） | 可考虑并入；保留原 LICENSE 与版权声明，在 README 致谢 |
| Apache-2.0 / BSD（第三方组件自带） | 只随 ST/CMSIS 官方渠道使用，不把「组件许可」误当「仓库授权」 |
| GPL-3.0 | 授权策略确定前不并入；若并入需整体同协议 |
| 无 LICENSE / NOASSERTION | **仅本地只读参考**，不复制代码进工程、不随仓库发布；需要时联系作者取得授权 |
| 正点原子官方例程 | 按官方资料盘授权条款使用，不自行改写授权声明 |

**Phase 8 上传 GitHub 前必须完成**：逐仓确认授权、保留版权头、生成第三方声明清单；否则只上传自己编写的代码与文档。
