# 音量键失效 / KEY0 长按变暂停 / 观感优化 / 默认封面 —— 实施说明

日期：2026-11-14 12:3x　固件：`Output/atk_f407.hex`（0 Error 0 Warning，Flash 826KB / RAM 66.8KB）

---

## 问题 1：两个音量键按下去没反应

### 根因（不是「按键没接」）

`WK_UP` 在探索者板上是**高电平有效**（PA0 通过按键接 3.3V，板上只有弱下拉）。
`key_init()` 里却把 PA0 和 PE2/PE3/PE4 一起配成了 `GPIO_PULLUP`：

```c
/* 改前 —— PA0 内部上拉，把「没按」读成了「一直按着」 */
g.Pull = GPIO_PULLUP;
g.Pin  = KEY1_PIN | KEY2_PIN | KEY0_PIN;  HAL_GPIO_Init(GPIOE, &g);
g.Pin  = WKUP_PIN;                        HAL_GPIO_Init(GPIOA, &g);
```

内部上拉（约 40k）压过板上弱下拉 → PA0 恒为高 → 固件认为「音量+被按住」：

- 上电 0.7s 后开始每 150ms 触发一次 `KEY_VOL_UP`，4 档一次，几秒就把音量顶到 63；
- 你按「音量−」→ 音量减到 59，**下一次扫描（10ms 后）又被顶回 63**；
- 两个键在观感上就都是「没反应」，屏幕上的 `VOL` 数字也几乎不动（因为一直在 63 附近）。

`KEY0/KEY1/KEY2` 是低有效，上拉是对的，所以切歌键一直正常 —— 这也解释了为什么只有音量键出问题。

### 修复

```c
/* 改后 —— WK_UP 单独配下拉（高有效），低有效的三个键保持上拉 */
g.Pull = GPIO_PULLUP;    g.Pin = KEY1_PIN | KEY2_PIN | KEY0_PIN;  HAL_GPIO_Init(GPIOE, &g);
g.Pull = GPIO_PULLDOWN;  g.Pin = WKUP_PIN;                        HAL_GPIO_Init(GPIOA, &g);
```

另外三处加固：

1. **「先松手才认」保险**：每个键要先被读到一次抬起（`armed`）才允许产生事件。
   万一某个键上电就是按下态（接触不良、被外壳压住），它不会把音量顶死。
2. **音量只走数字端**：`WM8978_SPKvol_Set()` 从按键路径里移除（模拟音量在开机时固定 0x30）。
   按键不再碰 I2C，杜绝「总线上卡住 → 主循环不动 → 所有键都没反应」这类连锁故障。
3. **开机打印原始电平**：`[7] KEY raw : 0x00`。手不按键时必须是 `0x00`；
   不是 0 就说明对应键被按住或引脚悬空（bit0=KEY0 bit1=KEY1 bit2=KEY2 bit3=WK_UP），一眼定位。

## 问题 2：KEY0 变成了暂停键

### 成因

**是我上一轮加的，不是硬件行为。** 当时你要求「要有播放/暂停」，而 4 个实体键都已被占用
（左右切歌 + 上下音量），没有空位，我就把 `KEY0` 长按 0.7s 借给了播放/暂停：

```c
/* key.c 里已删除的旧逻辑 */
if (i == 0u && !k->long_fired && k->hold_ms >= LONG_MS) {
    k->long_fired = 1;
    evt = KEY_PLAY;                       /* → main.c 发 'P'/'R' 给电脑 */
}
```

副作用：KEY0 变成「松手才切歌」，稍微按住久一点（>0.7s）就触发暂停，手感很怪。

### 修复

屏幕触屏按钮已经能播放/暂停了，实体键不需要再兼职。**长按逻辑整段删除**：

- `KEY0` = 下一首（按下即响应，不再等松手）；
- `KEY0` 长按不再有任何额外动作；
- `main.c` 里对应的 `KEY_PLAY` 分支一并删除（触屏按钮走自己的分支）。

## 问题 3：屏幕清晰度 / 观感

| 改动 | 之前 | 现在 |
|---|---|---|
| **英文歌词字宽** | ASCII 16×40，字母被压得很瘦 | **20×40**（`ASC40_W 20`，每行 3 字节，`draw_ascii40` 同步改） |
| **歌名字号** | 一律 32px（16px 放大 2×）或 16px | 优先 **40px 原生**（中文歌名 ≤6 字都放得下），放不下才降档 |
| **左栏信息区可读性** | 底图是照片/白底漫画，`h3R3`/`VOL`/时间几乎看不见 | 信息区（y≥248）加**渐变压暗遮罩**：248→320 线性压到 30%，以下固定 30% |
| **配色** | 非高亮歌词 0xCE79 / 译文 0x632C | 非高亮 **0xDEDB**（更亮）/ 译文 **0x7BEF** / 进度条底槽 0x39E7 |
| **长句折行** | 只按「最后一个放得下的空格」折，尾部会被截 | 选「**前后两半都放得下**的最后一个空格」，277 条单语行里只剩 1 条仍需三行（会被截 2~3 字） |

排版随之微调：`TITLE_Y 266→262`（给 40px 标题留高度），`ARTIST_Y 302→310`。

## 问题 4：没有封面的曲目统一用这张图

`gen_cover.py --song N` 会**整份重写** `cover_img.h`，直接拿它做默认封面会把第 5 首那张照片冲掉。
所以新写了 `Tools/add_default_cover.py`：先读出已有数组，再加入 `s_coverD / s_bgD`，合并写回。

```
保留: s_bg5, s_cover5
新增: s_coverD 112.5KB + s_bgD 93.8KB
```

`lcd_ui.c` 里：

```c
static const uint16_t *const s_covers[SONG_COUNT] = { s_coverD, s_coverD, s_coverD, s_coverD, s_cover5, s_coverD };
static const uint16_t *const s_bgs[SONG_COUNT]    = { s_bgD, s_bgD, s_bgD, s_bgD, s_bg5, s_bgD };
```

第 1~4、6 首显示这张漫画，第 5 首仍是原来的照片。左栏背景用同一张图模糊压暗后的横条。

⚠️ 代价：Flash 从 615.8KB 涨到 **825.7KB（1MB 的 81%）**。再加一张封面就会很紧张，
到时候要么砍一套字库，要么把封面改存到外部存储。


4. 播放/暂停只用屏幕中间那个按钮。
