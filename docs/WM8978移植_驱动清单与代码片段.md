### 1.5 可直接复制的 `wm8978.c` 核心段（适配后）

> 以下为**必须改写/必须存在**的部分；EQ/3D/MIC 增益等函数从摘录文件 `151-182`、`214-300` 行原样复制，把 `u8/u16` → `uint8_t/uint16_t` 即可（它们只调 `WM8978_Write_Reg` / `WM8978_Read_Reg`，不含 GPIO）。

```c
#include "./BSP/WM8978/wm8978.h"
#include "./BSP/IIC/myiic.h"

/* WM8978 的 IIC 只支持写、不支持读, 因此在本地缓存 58 个 9 位寄存器值 */
static uint16_t WM8978_REGVAL_TBL[58] =
{
    0X0000,0X0000,0X0000,0X0000,0X0050,0X0000,0X0140,0X0000,
    0X0000,0X0000,0X0000,0X00FF,0X00FF,0X0000,0X0100,0X00FF,
    0X00FF,0X0000,0X012C,0X002C,0X002C,0X002C,0X002C,0X0000,
    0X0032,0X0000,0X0000,0X0000,0X0000,0X0000,0X0000,0X0000,
    0X0038,0X000B,0X0032,0X0000,0X0008,0X000C,0X0093,0X00E9,
    0X0000,0X0000,0X0000,0X0000,0X0003,0X0010,0X0010,0X0100,
    0X0100,0X0002,0X0001,0X0001,0X0039,0X0039,0X0039,0X0039,
    0X0001,0X0001
};

/* 注意: 原版 Init 里的 GPIO 初始化段已整段删除, I2S 引脚由 i2s.c 负责 */
uint8_t WM8978_Init(void)
{
    uint8_t res;
    iic_init();                          /* 复用当前 HAL 工程的软件 IIC (PB8/PB9) */
    res = WM8978_Write_Reg(0, 0);        /* 软复位; 同时是 CODEC 在位的判据 */
    if (res) return 1;                  /* IIC 无 ACK -> 地址/丝印/接线有误 */

    WM8978_Write_Reg(1,  0X1B);         /* R1 MICEN / BIASEN / VMIDSEL=5K */
    WM8978_Write_Reg(2,  0X1B0);        /* R2 ROUT1/LOUT1 耳机输出使能 */
    WM8978_Write_Reg(3,  0X6C);         /* R3 LOUT2/ROUT2 喇叭输出 + MIXER */
    WM8978_Write_Reg(6,  0);            /* R6 MCLK/BCLK 由 STM32 外部提供 */
    WM8978_Write_Reg(43, 1 << 4);       /* R43 INVROUT2, 驱动 BTL 喇叭 */
    WM8978_Write_Reg(47, 1 << 8);       /* R47 左 MIC 20dB */
    WM8978_Write_Reg(48, 1 << 8);       /* R48 右 MIC 20dB */
    WM8978_Write_Reg(49, 1 << 1);       /* R49 TSDEN 过热保护 */
    WM8978_Write_Reg(10, 1 << 3);       /* R10 关软静音, 128x 过采样 */
    WM8978_Write_Reg(14, 1 << 3);       /* R14 ADC 128x */
    return 0;
}

/* 7 位寄存器地址 + 9 位数据: 首字节 = (reg<<1) | 数据最高位, 次字节 = 低 8 位 */
uint8_t WM8978_Write_Reg(uint8_t reg, uint16_t val)
{
    iic_start();
    iic_send_byte((WM8978_ADDR << 1) | 0);
    if (iic_wait_ack()) return 1;
    iic_send_byte((reg << 1) | ((val >> 8) & 0X01));
    if (iic_wait_ack()) return 2;
    iic_send_byte(val & 0XFF);
    if (iic_wait_ack()) return 3;
    iic_stop();
    if (reg < 58) WM8978_REGVAL_TBL[reg] = val;
    return 0;
}

uint16_t WM8978_Read_Reg(uint8_t reg)
{
    return (reg < 58) ? WM8978_REGVAL_TBL[reg] : 0;   /* 返回本地镜像, 不做 IIC 读 */
}

void WM8978_ADDA_Cfg(uint8_t dacen, uint8_t adcen)
{
    uint16_t regval = WM8978_Read_Reg(3);
    if (dacen) regval |= 3 << 0; else regval &= ~(3 << 0);
    WM8978_Write_Reg(3, regval);
    regval = WM8978_Read_Reg(2);
    if (adcen) regval |= 3 << 0; else regval &= ~(3 << 0);
    WM8978_Write_Reg(2, regval);
}

/* dacen: DAC 输出; bpsen: Bypass(麦克风/线路输入直通) —— 播放时务必传 0 */
void WM8978_Output_Cfg(uint8_t dacen, uint8_t bpsen)
{
    uint16_t regval = 0;
    if (dacen) regval |= 1 << 0;
    if (bpsen) { regval |= 1 << 1; regval |= 5 << 2; }
    WM8978_Write_Reg(50, regval);
    WM8978_Write_Reg(51, regval);
}

/* fmt: 0=LSB, 1=MSB, 2=飞利浦 I2S, 3=PCM/DSP; len: 0=16bit,1=20,2=24,3=32 */
void WM8978_I2S_Cfg(uint8_t fmt, uint8_t len)
{
    fmt &= 0X03;
    len &= 0X03;
    WM8978_Write_Reg(4, (fmt << 3) | (len << 5));     /* R4 */
}

void WM8978_HPvol_Set(uint8_t voll, uint8_t volr)      /* 0~63 */
{
    voll &= 0X3F; volr &= 0X3F;
    if (voll == 0) voll |= 1 << 6;                    /* 0 = mute */
    if (volr == 0) volr |= 1 << 6;
    WM8978_Write_Reg(52, voll);
    WM8978_Write_Reg(53, volr | (1 << 8));            /* HPVU=1 同步更新 */
}

void WM8978_SPKvol_Set(uint8_t volx)                   /* 0~63 */
{
    volx &= 0X3F;
    if (volx == 0) volx |= 1 << 6;
    WM8978_Write_Reg(54, volx);
    WM8978_Write_Reg(55, volx | (1 << 8));            /* SPKVU=1 同步更新 */
}

/* WM8978_Input_Cfg / MIC_Gain / LINEIN_Gain / AUX_Gain / 3D / EQ1~EQ5:
   从摘录 wm8978.c 第 116-133、151-182、214-300 行原样复制,
   仅把 u8/u16 换成 uint8_t/uint16_t; 它们只调用上面两个寄存器函数。 */
```

> 补充依据：当前 HAL 工程 `Drivers\BSP\IIC\myiic.c:102-126` 的 `iic_wait_ack()` 有 **250 次超时**并会 `iic_stop()` 返回 1，**不会死等**。所以 CODEC 不在位时程序不会卡死，只是 `WM8978_Init()` 返回非 0 —— 这也是第 6 节 L1 判据成立的原因（修正上一轮「可能阻塞导致枚举失败」的说法）。

## 5. 修改后的完整编译注意事项

1. **编译器**：`<uAC6>0</uAC6>` = AC5/armcc。MDK 5.37+ 缺 AC5 时先装 legacy ARM Compiler 5；不要盲切 AC6。
2. **器件包**：`Keil.STM32F4xx_DFP`，Device 保持 `STM32F407ZGTx`；宏保持 `USE_HAL_DRIVER,STM32F407xx,USE_USB_FS`。
3. **源文件增删**：`.uvprojx` 里 `es8388.c` → `wm8978.c`；新文件放 `Drivers\BSP\WM8978\`。IncludePath 已含 `..\..\Drivers`，`#include "./BSP/WM8978/wm8978.h"` 可解析（与现有 `./BSP/ES8388/...` 同风格）。
4. **类型别名**：HAL 版 `sys.h` **没有 `u8/u16`**（已核实），`wm8978.c/h` 全文替换为 `uint8_t/uint16_t`，否则大量 `unknown type name 'u8'`。
5. **StdPeriph 残留**：`WM8978_Init()` 里的 `RCC_AHB1PeriphClockCmd` / `GPIO_Init` / `GPIO_PinAFConfig` / `GPIO_Mode_AF` / `GPIO_Pin_9` 必须**全部删掉**（见 1.3 A4），否则编译报未定义，且会破坏 I2S 引脚。
6. **IIC 函数名**：`IIC_Init/Start/Send_Byte/Wait_Ack/Stop` → `iic_init/start/send_byte/wait_ack/stop`（当前 `myiic.h:59-66`）。二者的 ACK 语义一致（0=成功），无需改逻辑。
7. **不要给 `WM8978_Read_Reg` 加真实 IIC 读**：WM8978 只写；`WM8978_REGVAL_TBL[58]` 镜像必须建立，否则 ADDA/Input/音量等读-改-写函数会把寄存器清成 0。
8. **检查 `WM8978_Init()` 返回值**：原 `es8388_init()` 调用未判返回值；新代码必须判，这是 L1 判据。
9. **参数编码**：`WM8978_I2S_Cfg(2,0)`、`WM8978_Output_Cfg(1,0)`、`HPvol_Set(voll,volr)` 三处与 ES8388 编码不同，按第 2 节逐字替换。
10. **保持 48 kHz**：本轮不动 `USBD_AUDIO_FREQ` / 描述符 / PLLI2S 查表。若有人顺手改成 44100，会与 `AUDIO_OUT_PACKET`、等时反馈、I2S 分频不同步，出现爆音——**本轮禁止改**。
11. **授权**：若采用 `bangkr` 骨架，Phase 8 上传 GitHub 前必须换 MIT 来源或取得授权；当前仅本地验证。
12. **产物**：`Output\atk_f407.hex`（`CreateHexFile=1`），Flash 算法 `STM32F4xx_1024.FLM`；编译前建议清空 Output 或另存 hex 名，避免误烧旧 ES8388 固件。
13. **预期编译结果**：0 Error。若出现 `undefined symbol es8388_*`，说明还有调用点没换（对照第 2 节 10 处清单）；若出现 `undefined symbol iic_*`，说明 IIC 名没映射。

## 6. 烧录后的测试判断标准（分层，可观测可判定）

> 烧录由人工执行；智能体不烧录、不听音、不声称「已出声」。以下每条都要由你实测确认。

| 层级 | 操作 | ✅ 通过判据 | ❌ 不通过时排查 |
|---|---|---|---|
| **L0 上电** | 供电、接 CH340 调试串口 | LED0 周期性闪烁；串口 115200 有输出；LCD 显示 `STM32 / USB Sound Card TEST / VOLUME:70` | 供电 / 复位 / 晶振 / BOOT0 / SWD 上电五步法 |
| **L1 CODEC 在位**（新增最关键判据） | 看串口与 LCD | **没有** `WM8978 Init FAIL`；`WM8978_Init()` 返回 0，即 IIC 向 `0X1A` 软复位拿到 ACK | 丝印是否为 WM8978；IIC PB8/PB9；`WM8978_ADDR`；软件 IIC 上拉；`iic_wait_ack()` 超时返回 1 |
| **L2 USB 枚举** | USB 线插 USB_SLAVE；V2.7 USB/CAN 跳线置 USB 侧 | 设备管理器出现 `USB\VID_0483&PID_5730` 的 `STM32 AUDIO Streaming in FS Mode`；LCD `USB Connected`；LED1 常亮 | USB 线是否插错 USB_232；USB_HOST 是否插了设备；PA11/PA12 AF10；跳线位置 |
| **L3 I2S/DMA 启动** | 用电脑播放任意音频 | 串口出现 `EVAL_AUDIO_Init:70,48000`；程序不 HardFault | `WM8978_I2S_Cfg(2,0)` 是否写对；`i2s_init(...)` 是否被误改；`i2s_samplerate_set(48000)` 查表 |
| **L4 出声** | Windows 声音输出选该声卡，格式 48 kHz / 16 bit / 2 声道 | PHONE 耳机或 SPK 绿色端子喇叭**能听到声音** | L1 通过但 L4 失败 → 查 R1/R2/R3/R10/R50/R51 寄存器序列、`WM8978_Output_Cfg(1,0)`、`WM8978_ADDA_Cfg(1,0)`、音量非 0；示波器看 LRCK/BCLK/MCLK/DACDAT |
| **L5 音量与静音** | KEY0/KEY2；系统静音/取消 | LCD 音量数值变化且**实际音量随之变化**；静音后无声、取消后恢复 | `g_volume*0.63` 是否落在 0~63；`HPvol_Set(voll,volr)` 双参数；`SetMute` 是否误用 `Output_Cfg` |
| **L6 稳定性** | 连续播放 5–10 分钟 | 无爆音、无断流、无卡死 | 48 kHz 等时与 I2S 的 ±4 B 反馈补偿是否被误改；环形缓冲是否被覆盖 |

**分层意义**：L1 单独成立说明 CODEC 已在位且 IIC 通；L2 成立说明 USB 栈完好（与 CODEC 无关）；L4 才检验 CODEC 配置。这样「能枚举但无声」可直接定位到 C1–C5 的寄存器配置，而不是怀疑 USB 或硬件坏了。

> 补充：`myiic.c:102-126` 的 `iic_wait_ack()` 有 250 次超时，CODEC 不在位时不会死循环，只会让 `WM8978_Init()` 返回 1 并走 L1 的失败提示——所以「枚举成功但无声」是最可能的失败形态。

## 7. 四件套

**① 原理说明**：只换 CODEC 层能成立，是因为音频链被切成两段——USB 侧（HAL PCD + UAC ISOC + 环形缓冲 + I2S2/DMA）与 CODEC 侧（软件 IIC 配置 WM8978 寄存器）通过 `BSP_AUDIO_OUT_*` 这一层 BSP 接口解耦。只要新驱动提供等价的 Init/ADDA/Input/Output/I2S/Volume 语义，USB 与 I2S 代码无需改动。关键差异是 WM8978 的 **7 位地址 + 9 位数据 + 只写不读（需寄存器镜像）**，以及**参数编码与 ES8388 完全不同**。

**② 完整代码**：本文件第 1.4 / 1.5 / 2 节给出可直接复制的 `wm8978.h`、核心 `wm8978.c`、以及 C1–C5 全部 10 处「原文 → 改后」片段，并标注文件与行号。**均未写入工程**。

**③ 预期现象**：改对后按 L0–L6 逐层通过；仍是 **48 kHz UAC 1.0** 声卡，不是 44.1 kHz CDC 主线。本轮没有编译、烧录、枚举、出声、上传。

**④ 故障排查清单**：见第 5 节 13 条编译项、第 6 节分层判据表，以及「参数/语义对照表」的陷阱列。
